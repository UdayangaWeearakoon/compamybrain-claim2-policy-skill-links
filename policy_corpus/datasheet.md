## Source

Action-Based Conversations Dataset (ABCD), Chen et al. 2021, NAACL-HLT 2021,
arXiv:2104.00783. Specifically, the agent guideline manual as distributed in
the official repository at `data/guidelines.json`, cross-referenced against
`data/kb.json` (intent → gold agent action sequence) and `data/ontology.json`
(flow/subflow taxonomy, enumerable slot values). ABCD contains 10,942
human-to-human dialogues across 55 customer-service intents (subflows),
grouped into 10 flows, each dialogue grounded in this same written guideline
manual.

## Construction procedure

1. **Intent-family grouping (55 subflows → 37 policy documents).** ABCD's
   55 subflows were grouped wherever two or more subflows share an
   (near-)identical gold agent action-sequence template, as recorded in
   `kb.json` (e.g., the three "Return Due to Stain/Color/Size" subflows all
   run `pull-up-account → validate-purchase → membership → enter-details →
   update-order` and were merged into one "Product Return Policy"). The two
   FAQ flows (`single_item_query`, `storewide_query`, 4 subflows each) were
   each collapsed to a single family because they share one lookup-and-cite
   procedure differentiated only by topic. Subflows with no shared action
   template were kept one-to-one. This yields exactly 37 families, covering
   all 55 subflows with no overlap and no omission (verified
   programmatically at build time), within the 25–40 target band from the
   execution guide.
2. **Rule extraction.** For each family, the ABCD guideline text
   (per-subflow `instructions` plus per-action `text`/`subtext` for every
   button in that subflow) was read in full and reduced to explicit,
   testable if/then rule statements — one rule per distinct procedural or
   eligibility requirement. Every concrete number in this corpus (day
   windows, dollar thresholds, membership-tier cutoffs, option counts) is
   taken **verbatim** from the ABCD guideline text; none were invented.
   Examples: the $50 default refund amount (Initiate Refund), the 6-month /
   90-day / 30-day return windows by membership tier (Return subflows), the
   7-day promo-code and mistimed-billing thresholds, the $8.00 standard
   shipping fee, the $99/year subscription price, and the 1-day-late Silver
   extension cutoff are all copied from the source manual, not fabricated.
3. **Uniform rendering.** All 37 v1 documents were generated by a single
   Python template (`scripts/build_policy_corpus_v1.py`) in one pass, so
   document structure, field order, and rule phrasing style are uniform
   across the whole corpus. This is deliberate: Phase 3 will write v2
   documents that supersede specific rules by `rule_id`, and a downstream
   text-similarity baseline must not be able to distinguish v1 from v2 on
   writing style alone — only on rule content.
4. **Provenance.** Every document records its ABCD `flow` and
   `source_subflows` (ontology keys), so any policy document can be traced
   back to the exact ABCD subflow(s) it governs.
5. **Freeze.** Once built, every file was hashed with SHA-256
   (`scripts/freeze_and_hash.py`), a corpus-level fingerprint was computed
   as the SHA-256 of the sorted `filename:hash` lines, and all files were
   made read-only (`chmod 444`). No file under `policy_corpus/v1/` may be
   edited after this point; any policy change is a new version written to
   `policy_corpus/v2/` in Phase 3, referencing superseded `rule_id`s.

## Structure of each policy document

Each policy JSON contains: `policy_id` (POL-001…POL-037), `family` (title),
`version` (`v1` for all documents in this freeze), `effective_timestamp`
(`2021-06-01T00:00:00Z` for the whole v1 corpus — chosen as ABCD's
publication month, representing the notional baseline policy state the
dialogues were collected under; a construction choice, not a claim about
ASAPP's internal versioning history), `flow`, `source_subflows`, `source`,
`supersedes` (null for v1), and `rules` (a list of `{rule_id, statement}`
objects, `rule_id` = `<policy_id>-R<n>`).

## Corpus statistics

- 37 policy documents, covering all 55 ABCD subflows, 10 flows.
- 123 total rules (min 2, max 5 rules per document; mean ≈ 3.3).
- Every rule is a testable statement referencing a concrete gold action
  (e.g., Offer Refund, Update Account, Verify Identity), a concrete
  parameter (dollar amount, day count, membership tier, or enumerated
  option set), or both — per the execution guide's testability bar
  ("refunds over $100 require identity verification" is testable; "handle
  refunds carefully" is not).

## Known limitations

- **Family boundary is an editorial choice.** The action-sequence-identity
  grouping rule is objective and reproducible, but ABCD does not itself
  label "intent families" — this corpus imposes that structure. A
  different, defensible grouping (e.g., flow-level, 10 documents, or fully
  atomic, 55 documents) would change which skills later share a dependency
  link, though not the count of underlying testable rules.
- **Deterministic construction, not LLM-distilled.** Per the execution
  guide, v1 documents should be uniform in style "drafted in one pass, or
  passed through the same rewriting prompt." This corpus was built via a
  single deterministic Python template rather than an LLM rewriting pass;
  style uniformity is therefore exact (byte-identical structure) rather
  than approximately uniform. This is stated explicitly because Phase 4's
  contamination discussion assumes an LLM-mediated construction step
  elsewhere in the pipeline (skill distillation, Phase 2) — the *policy
  corpus itself* has no LLM in its construction path, which if anything
  strengthens the "policy text is novel and not memorized" argument for v2
  supersessions written later.
- **Two FAQ families (POL-036, POL-037) are lower business-rule density.**
  Their "rules" are largely scope and format constraints (which topics are
  in-scope, restate-don't-copy) rather than eligibility/threshold logic.
  They were kept in the corpus because ABCD treats them as full subflows
  with gold action sequences, but they are expected to contribute fewer
  strong supersession cases in Phase 3 than the tier-gated policies (returns,
  refunds, extensions, disputes).
- **Some rules paraphrase rather than quote ABCD's guideline text.**
  Procedural language ("must", "before X, the agent must Y") was added to
  convert descriptive guideline prose into imperative testable rules; the
  underlying facts (numbers, tiers, options) are unchanged from source.

## Non-negotiable hygiene applied at this step

- Every file hashed (SHA-256) and the corpus frozen (read-only) before any
  skill distillation (Phase 2) begins.
- No LLM calls were made in this step (see Known limitations); nothing to
  log for this phase under hygiene rule #3.
